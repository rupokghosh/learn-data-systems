Coping with load

You can now describe load and measure performance. The next question: how do you keep performance good as load keeps growing?

Busy servers get slow suddenly

Requests do not arrive evenly. They come at random, so sometimes several land at once and have to wait in a queue. The busier a server is, the longer each queue takes to drain. As utilization approaches 100%, waiting time does not grow steadily. It shoots up.

A few slow requests make it worse: everything queued behind them waits too. This is called head-of-line blockinghead-of-line blocking: Fast requests stuck waiting behind a slow one at the front of the queue..

In a simple queueing model, waiting time grows like 1 ÷ (1 − utilization). Going from 50% to 90% busy makes the average request five times slower, even though the load did not even double.

Scaling up or scaling out

When one machine is not enough, you have two broad options.

Scale upScale out
HowBuy a more powerful machine.Spread the load across many machines that share nothing.
You gainSimplicity. No distributed-systems problems.No hard ceiling, and the system survives one machine dying.
You payCost rises steeply at the top end, there is a ceiling, and one machine is one point of failure.Much more complexity, especially for data that lives on the machines.

Stateless services, like web servers, are easy to scale out: add copies behind a load balancer. Stateful systems, like databases, are much harder, because the data itself has to be split and copied. That is why many teams keep their database on one machine until they truly must distribute it. Later chapters on replication and partitioning are all about doing that well.

Some systems are elastic: they add machines automatically when load rises. Others are scaled by hand. Elastic is useful when load is unpredictable; manual is simpler and has fewer surprises.

There is no general-purpose, magic scaling recipe. An architecture that scales well is built on assumptions about which operations will be common and which rare: your load parameters. Get those wrong and the scaling effort is wasted.
