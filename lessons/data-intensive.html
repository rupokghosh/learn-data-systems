What makes an application data-intensive?

Most applications today are not limited by raw computing power. Their hard problems are about data: how much there is, how complex it is, and how fast it changes.

Built from standard parts

Few teams write a database from scratch. Instead, they combine well-known building blocks:

  • Databases store data so you can find it again later.
  • Caches remember the result of an expensive operation to make reads faster.
  • Search indexes let users search by keyword or filter.
  • Stream processing sends messages to other processes to handle asynchronously.
  • Batch processing periodically crunches a large pile of accumulated data.

When you hide several of these tools behind one API, you have built a new, special-purpose data system. Your application code is the glue, and you are now responsible for keeping every copy of the data consistent.

Three concerns that run through everything

Whatever you build from these parts, three questions keep coming back. The rest of this chapter takes them one at a time.

  • Reliability: keep working correctly, even when hardware, software, or people make mistakes.
  • Scalability: have a sensible plan for when traffic, data, or complexity grows.
  • Maintainability: let many people run and change the system productively, for years.
